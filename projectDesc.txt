PRODUCT FILTER DASHBOARD

Purpose

A Vanilla JavaScript project to revise and practice frontend concepts
properly. We will build it step-by-step, one concept at a time.

Tech

-   HTML
-   CSS
-   Vanilla JavaScript
-   DOM
-   Events
-   Array methods
-   localStorage
-   Fetch API
-   Async JavaScript
-   Error handling

IMPORTANT LEARNING RULE

Do not jump straight to full solutions. For each feature: 1. Understand
the requirement. 2. Decide the approach. 3. Write the code yourself. 4.
Test it. 5. Fix mistakes. 6. Then move to the next concept.

PROJECT FEATURES

1. PRODUCT DATA

Create a product array containing objects.

Each product should have: - id - name - category - price - rating -
image (optional)

Example categories: - Electronics - Clothing - Shoes - Books -
Accessories

Example products: - iPhone 15 - Samsung Galaxy - Laptop - Headphones -
T-Shirt - Jeans - Running Shoes - Java Book - Backpack - Smart Watch

2. PRODUCT RENDERING

Render products dynamically into the DOM.

Practice: - querySelector - createElement / innerHTML - map() - template
literals - append/render - clearing old products before rendering

Goal: Understand how JavaScript takes data and creates UI.

3. SEARCH

Add a search input.

Requirement: When the user types: “phone”

Only products whose name contains “phone” should remain.

Important: - Search should be case-insensitive. - Use includes(). - Do
not modify the original product array.

Practice: - input event - value - trim() - toLowerCase() - filter()

4. CATEGORY DROPDOWN

Add a category dropdown.

Dropdown options:

-   All Categories
-   Electronics
-   Clothing
-   Shoes
-   Books
-   Accessories

Behavior: - “All Categories” shows every product. - Selecting a category
shows only products from that category.

The dropdown should ideally be generated from the available category
data rather than hardcoding duplicate values later.

Practice: - change event - select.value - filter()

5. COMBINED SEARCH + CATEGORY FILTER

Search and category filtering must work together.

Example: Search = “phone” Category = Electronics

Result: Only electronics products whose name contains “phone”.

Important idea: Do NOT create separate unrelated render systems.

Use one filtering pipeline.

Concept: products -> search filter -> category filter -> sorting ->
price filter -> render

6. SORTING

Add a sort dropdown.

Options:

-   Default
-   Price: Low to High
-   Price: High to Low
-   Rating: High to Low
-   Name: A to Z
-   Name: Z to A

Important: Sorting should happen after filtering.

Practice: - sort() - comparison function - numbers vs strings - avoiding
accidental mutation of original data

7. PRICE FILTER

Add a price filter.

Possible UI: - Minimum price input - Maximum price input

Example: Min = 500 Max = 2000

Only products between those values should be shown.

Handle: - empty min - empty max - both empty - minimum greater than
maximum

8. EMPTY STATE

If no products match the current filters, do not leave a blank area.

Show something like:

“No products found.”

Example: Search = “xyzabc”

Result: No products found.

9. PRODUCT COUNT

Show the number of currently visible products.

Examples:

“10 products” “3 products” “No products”

The count should update whenever filters or sorting change.

10. RESET FILTERS

Add a Reset button.

When clicked: - Search becomes empty. - Category becomes All
Categories. - Sort becomes Default. - Min price becomes empty. - Max
price becomes empty. - All products are shown again.

11. LOCALSTORAGE

Persist useful user state using localStorage.

Possible things to store: - selected filters - search text - selected
category - selected sorting option - price range

On page reload: Restore the previous filter state.

Practice: - localStorage.setItem() - localStorage.getItem() -
JSON.stringify() - JSON.parse() - use of localStorage safely

12. FAVORITES / WISHLIST (OPTIONAL EXTENSION)

Add a favorite button to each product.

Requirements: - User can favorite/unfavorite products. - Favorites
survive page reload. - Store favorite product IDs in localStorage.

Practice: - event handling - data attributes - array methods -
localStorage - state synchronization

13. FETCH API

Replace the local product array later with API data.

Flow:

fetch() -> response -> response.json() -> products -> render()

Practice: - fetch() - Promise - then() - async/await - response.ok

14. LOADING STATE

While products are being fetched, show:

“Loading products…”

After successful fetch: Hide loading message and render products.

15. ERROR HANDLING

If the API request fails:

Show:

“Failed to load products. Please try again.”

Practice: - try/catch - response.ok - network errors - user-friendly
error messages

16. RETRY

Add a Retry button when API loading fails.

Clicking Retry should attempt the fetch again.

17. EVENT DELEGATION

If product cards contain buttons such as: - Favorite - Add to cart -
View details

Practice event delegation instead of attaching unnecessary listeners to
every button.

Learn: - event.target - closest() - data-id - bubbling

18. PRODUCT DETAILS

Optional feature.

Clicking a product can show: - name - price - category - rating -
description - image

Can be implemented using: - modal OR - details section

19. CART (OPTIONAL EXTENSION)

Add: - Add to Cart - quantity - remove - total price

Persist cart using localStorage.

This is an extension and should NOT be done until the filtering
dashboard itself is solid.

FINAL PROJECT FLOW

DATA | v RENDER PRODUCTS | v SEARCH | v CATEGORY FILTER | v PRICE FILTER
| v SORT | v EMPTY STATE + COUNT | v RENDER
